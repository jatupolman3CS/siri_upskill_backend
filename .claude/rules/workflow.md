# Workflow Rules

## ลำดับการทำงานทุกงาน

1. **เข้าใจก่อน** — อ่าน requirement ที่เกี่ยว (`docs/REQUIREMENTS.md`) + โค้ดรอบข้าง ก่อนเขียนบรรทัดแรก
2. **เช็ค blocking decision** — งานนี้แตะ Q1–Q5 ใน `docs/DECISIONS.md` หรือเปล่า ถ้าใช่และยังไม่ตัดสิน → ถามก่อน
3. **วางแผนสั้น ๆ** ถ้างานแตะเกิน 3 ไฟล์ หรือมีผลกับ schema/สัญญา API — เสนอแผนให้ user เห็นก่อนลงมือ
4. **ทำ** ตาม rule ของ layer นั้น
5. **รันจริง** — build + test ให้ผ่านก่อนบอกว่าเสร็จ
6. **รายงานตามจริง** ทำอะไรไปบ้าง, ไฟล์ไหน, อะไรที่ยังไม่ได้ทำและเพราะอะไร

## Definition of Done

งานหนึ่งชิ้นจะถือว่าเสร็จเมื่อครบทุกข้อ:

- [ ] `dotnet build` ผ่าน ไม่มี warning ใหม่
- [ ] `dotnet test` และ `npm run test` ผ่านทั้งหมด
- [ ] มีเทสต์ครอบ logic ใหม่ (business rule / การคำนวณเงิน / การตัดสินสิทธิ์)
- [ ] มี authorization + ownership check ในทุก endpoint ที่แตะข้อมูลของผู้ใช้
- [ ] มี migration ถ้าแตะ schema และอ่านตรวจแล้วว่าไม่ทำข้อมูลหาย
- [ ] จัดการ loading / error / empty state ครบในฝั่ง UI
- [ ] ไม่มี secret, ไม่มี `console.log`, ไม่มีโค้ดที่ comment ทิ้ง
- [ ] ข้อความ user-facing อยู่ในไฟล์ i18n
- [ ] อัปเดตเอกสารที่เกี่ยวข้องถ้าพฤติกรรมของระบบเปลี่ยน

## Git

- Branch: `feat/<phase>-<slug>`, `fix/<slug>`, `chore/<slug>`
- Commit: Conventional Commits ภาษาอังกฤษ — `feat(catalog): add course search filters`
- 1 commit = 1 การเปลี่ยนแปลงที่สมเหตุสมผล ห้ามยัดทุกอย่างเป็น commit เดียว
- **ห้าม commit / push / สร้าง PR เอง** เว้นแต่ user สั่ง
- ห้าม `--no-verify`, ห้าม force push ไป branch หลัก
- ห้าม commit: `appsettings.Development.json` ที่มีค่าจริง, `*.user`, `bin/`, `obj/`, `node_modules/`, ไฟล์วิดีโอ

## สื่อสารกับ user

- ตอบเป็นภาษาไทย กระชับ ตรงประเด็น
- อ้างไฟล์เป็น path พร้อมเลขบรรทัดเมื่อชี้จุดเฉพาะ
- เจอปัญหาที่นอกขอบเขตงาน → บอก แต่ **อย่าไปแก้เอง**
- ไม่แน่ใจเรื่องที่ตัดสินใจแล้วผลต่างกันมาก → ถาม อย่าเดา
- ห้ามพูดว่า "เสร็จแล้ว" ถ้ายังไม่ได้รัน build/test จริง ถ้ารันแล้วแดงให้แสดง output ตรง ๆ

## เมื่อ requirement ขัดกัน

`docs/REQUIREMENTS.md` (มาจากเอกสารลูกค้า) มีน้ำหนักเหนือ `docs/*` ตัวอื่นที่เป็นการตีความ
ถ้าพบว่าขัดกันจริง → หยุด แล้วรายงานความขัดแย้งพร้อมทางเลือก อย่าเลือกเองเงียบ ๆ

## Phase discipline

ทำตามลำดับใน `docs/ROADMAP.md` — ห้ามเริ่มงาน phase ถัดไปก่อน exit criteria ของ phase ปัจจุบันผ่าน
ถ้า user สั่งข้าม ให้ทำตามแต่บอกผลกระทบสั้น ๆ ครั้งเดียว
